# IELTS Translator — Phase 3: Quiz — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ba loại quiz (`FILL_BLANK`, `COLLOCATION_CHOICE`, `FREE_WRITE`) sinh sẵn và cache trong DB, chấm tại chỗ với `FREE_WRITE` do Gemini chấm, hiện ở tab thứ tư của side panel — và lịch ôn SRS không đổi một dòng nào.

**Architecture:** Module `quiz` mới ở backend **đọc** `srs_card` qua một native query đặt trong chính `quiz` để chọn ứng viên, nhưng **không bao giờ ghi** vào `srs_card`/`review_log`. Đề sinh theo lô (một call Gemini cho mỗi loại, không phải mỗi từ), lưu vào `quiz_item` kèm `prompt_version` để tái dùng, và `QuizItemDto` gửi xuống panel **không mang đáp án**. Timeout Gemini tách thành ba mức qua enum, timeout phía extension bọc bằng `AbortSignal.timeout()` — hai việc này sửa lan sang code Phase 1.

**Tech Stack:** Java 21, Spring Boot 3.4.1 (Web MVC, JPA, Flyway, Bean Validation), Postgres 16, hypersistence-utils, WireMock, Testcontainers; React 18 + TypeScript 5.7, Vite 5 + CRXJS, Vitest + RTL.

**Spec:** [`docs/superpowers/specs/2026-08-06-phase2-3-srs-quiz-design.md`](../specs/2026-08-06-phase2-3-srs-quiz-design.md) mục 3 (Phase 3), mục 4 (sai lệch), mục 5 (thứ tự thực thi).
**Design gốc:** [`docs/superpowers/specs/2026-08-03-ielts-translator-extension-design.md`](../specs/2026-08-03-ielts-translator-extension-design.md) mục 9.

## Global Constraints

- Comment code, message lỗi, text hiển thị viết bằng **tiếng Việt đủ dấu**. Tên class/biến/hàm/package giữ tiếng Anh. Lưu UTF-8.
- **Không Lombok.** Constructor injection thủ công, `record` cho DTO, field `final` khi được.
- **Không thêm dependency mới.** Bean Validation, `RestClient`, Jackson đều đã có trong `spring-boot-starter-*`.
- Content script / side panel / Options **không bao giờ** gọi HTTP — mọi request qua service worker.
- Luồng mới = thêm interface request + thêm vào union `ExtensionRequest` + thêm vào `ResponseMap`, rồi mới xử lý ở service worker. Không gửi message ad-hoc bằng object rời.
- `shared/types.ts` là bản gương của DTO backend. Đừng bịa field backend không có.
- Mọi lỗi hình dạng `{ code, message, retryable }`. **Không thêm `ErrorCode` mới** — `GlobalExceptionHandler.statusFor()` là switch exhaustive, thêm mã mới mà quên nhánh là fail compile. Mã hợp lệ: `GEMINI_QUOTA`, `GEMINI_UNAVAILABLE`, `PARSE_ERROR`, `TEXT_TOO_LONG`, `NOT_FOUND`, `INTERNAL`.
- Gọi Gemini **luôn** dùng structured output (`responseSchema`). Không bao giờ parse text tự do.
- Prompt nằm ở `backend/src/main/resources/prompts/*.md`, có header `version: N`. **Sửa nội dung prompt phải tăng `version:`** — đó là cách duy nhất làm đề cũ hết hiệu lực.
- `application.yml` **không hardcode giá trị nào** — mọi mục viết `${BIEN:mặc-định}`. Thêm config mới → thêm vào `.env.example` **và** bảng "Biến môi trường" trong `README.md`.
- Migration Flyway **append-only**. Không sửa `V1`–`V4`. Entity JPA phải khớp schema (`ddl-auto: validate` fail khi lệch).
- **`quiz` đọc `srs_card` nhưng KHÔNG BAO GIỜ ghi.** Kiểm chứng bằng `QuizSrsIsolationIT`, không chỉ bằng lời hứa.
- Surefire include cả `**/*Test.java` (unit, không cần Docker) và `**/*IT.java` (integration, kế thừa `AbstractPostgresIT`). **Đặt sai tên file = test bị bỏ qua im lặng.**
- `npm run build` là nơi **duy nhất** chạy type check (`tsc --noEmit && vite build`). Test xanh mà build đỏ vẫn là hỏng — luôn chạy cả hai trước khi báo xong.
- TypeScript bật `strict` **và** `noUnusedLocals`.
- **Không bao giờ chạy `docker compose down -v`** — xoá volume `ielts_pgdata` là xoá sạch sổ từ vựng.
- `mvn test` cần Docker chạy sẵn cho Testcontainers.
- Nhánh hiện tại là `main`. **Hỏi trước khi commit.**

## Hợp đồng API — chốt trước, hai phía không được lệch

Backend (nhóm A) và extension (nhóm B) chạy song song. Hai bên **chỉ** được dựa vào phần này, không hỏi nhau giữa chừng. Đổi hợp đồng = dừng cả hai, sửa plan, rồi chạy tiếp.

```
POST /api/quiz/generate
  Request:  { vocabIds?: number[], count?: number, types?: string[] }
            đúng MỘT trong vocabIds / count phải có mặt → nếu không: HTTP 400
            types rỗng hoặc thiếu → mặc định cả ba loại
  Response: QuizItemDto[]        (200; mảng RỖNG khi không có ứng viên — KHÔNG phải lỗi)

POST /api/quiz/answer
  Request:  { quizItemId: number, answer: string }     answer LUÔN là string
  Response: AnswerResult                               (200)
            quizItemId không tồn tại → NOT_FOUND (404)
```

```ts
type QuizType = 'FILL_BLANK' | 'COLLOCATION_CHOICE' | 'FREE_WRITE';

interface QuizItemDto {
  id: number;
  type: QuizType;
  vocabEntryId: number;
  term: string;
  question: string;            // đề bài hiển thị, tiếng Việt
  sentence: string | null;     // chỉ FILL_BLANK — câu có "___"
  options: string[] | null;    // chỉ COLLOCATION_CHOICE — đúng 4 phần tử, thứ tự như đã lưu
}

interface AnswerResult {
  correct: boolean;
  score: number;                     // 0–100
  feedback: string;                  // tiếng Việt, luôn có
  improvedVersion: string | null;    // chỉ FREE_WRITE mới khác null
}
```

**Bất biến không được vi phạm:**

1. `QuizItemDto` **không có** field đáp án. Không `answer`, không `correctIndex`, không gì suy ra được đáp án. `QuizControllerIT` khẳng định điều này bằng cách so chuỗi JSON thô.
2. `options` giữ **đúng thứ tự đã lưu trong `payload`**. Không trộn lại lúc trả về — trộn lại mà `correct_index` giữ nguyên là chấm sai toàn bộ.
3. `answer` cho `COLLOCATION_CHOICE` là **chuỗi chứa số index** (`"2"`). Parse không được → tính **sai**, không phải lỗi.
4. Không có ứng viên → `[]`. Panel hiện empty state, không hiện lỗi đỏ.

### Task A1: Tách timeout Gemini thành ba mức  ⚠️ SỬA LAN PHASE 1

**Nhóm:** backend. **Phụ thuộc:** không.

Spec mục 3.11. `GeminiProperties.timeoutSeconds` hiện là **một** giá trị 15s nướng vào `ClientHttpRequestFactory` trong `GeminiConfig`. Sinh quiz cần 30s, chấm bài cần 20s.

**Rủi ro hồi quy:** `generateJson(String, Map)` có **2 call site ở main** (`TranslationService:67`, `DistractorGenerator:108`) và **21 call site ở test** (`GeminiClientTest`, `TranslationServiceIT`, `TranslateControllerIT`, `DistractorGeneratorIT`). Đổi chữ ký thành bắt buộc truyền `GeminiTimeout` là làm đỏ toàn bộ. `GeminiClientTest` còn **tự dựng `GeminiClient` bằng constructor 3 tham số** — đổi constructor là làm đỏ thêm 11 test nữa của Phase 1.
→ **Giữ nguyên cả overload cũ lẫn constructor cũ.** Cái cũ mặc định về `TRANSLATE`. Đây là điều kiện để biết chắc Phase 1 không vỡ: nếu có test Phase 1 nào đỏ, đó là hồi quy thật, không phải "test cần cập nhật".

import org.springframework.context.annotation.Configuration;
import org.springframework.http.client.SimpleClientHttpRequestFactory;

@Configuration
public class GeminiConfig {

    /** Bắt tay TCP không phụ thuộc độ dài output nên dùng chung cho cả ba mức. */
    private static final Duration CONNECT_TIMEOUT = Duration.ofSeconds(5);

    /**
     * Bean tên {@code geminiRestClient} giữ nguyên tên cũ: đây là client mức TRANSLATE,
     * và giữ tên để mọi chỗ inject theo tên từ Phase 1 không vỡ.

        return build(props.baseUrl(), props.timeoutSeconds());
    }

    public Map<GeminiTimeout, RestClient> geminiRestClients(GeminiProperties props) {
        Map<GeminiTimeout, RestClient> clients = new EnumMap<>(GeminiTimeout.class);
        clients.put(GeminiTimeout.TRANSLATE, build(props.baseUrl(), props.timeoutSeconds()));
        clients.put(GeminiTimeout.QUIZ_GENERATE,
                build(props.baseUrl(), props.quizGenerateTimeoutSeconds()));
        clients.put(GeminiTimeout.QUIZ_GRADE,
                build(props.baseUrl(), props.quizGradeTimeoutSeconds()));
        return clients;
    }

    private RestClient build(String baseUrl, int readTimeoutSeconds) {
        SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(CONNECT_TIMEOUT);
        factory.setReadTimeout(Duration.ofSeconds(readTimeoutSeconds));
        return RestClient.builder()
                .requestFactory(factory)
                .baseUrl(baseUrl)
                .build();
    }

    public GeminiClient(Map<GeminiTimeout, RestClient> geminiRestClients,

        this.props = props;
        this.objectMapper = objectMapper;
    }

    /**
     * Dựng client dùng CHUNG một RestClient cho cả ba mức. Chỉ dùng trong test đơn vị —
     * giữ lại để 11 test Phase 1 của GeminiClientTest không phải viết lại.
     */
    public GeminiClient(RestClient geminiRestClient, GeminiProperties props, ObjectMapper objectMapper) {
        this(sameClientForAllTiers(geminiRestClient), props, objectMapper);
    }

    private static Map<GeminiTimeout, RestClient> sameClientForAllTiers(RestClient client) {
        Map<GeminiTimeout, RestClient> map = new EnumMap<>(GeminiTimeout.class);
        for (GeminiTimeout tier : GeminiTimeout.values()) {
            map.put(tier, client);
        }
        return map;
    }

    /** Đường cũ của Phase 1 — mặc định mức TRANSLATE. Giữ nguyên để 2 call site cũ không đổi. */
    public JsonNode generateJson(String prompt, Map<String, Object> responseSchema) {
        return generateJson(prompt, responseSchema, GeminiTimeout.TRANSLATE);
    }

    /**
     * Gọi Gemini với structured output ở mức timeout {@code tier}. Chỉ retry lỗi tạm thời
     * (5xx, timeout, JSON hỏng) đúng 1 lần. Lỗi quota không retry.
     */
    public JsonNode generateJson(String prompt, Map<String, Object> responseSchema,
                                 GeminiTimeout tier) {
        AppException last = null;
        for (int attempt = 1; attempt <= MAX_ATTEMPTS; attempt++) {
            try {
                return callOnce(prompt, responseSchema, tier);
            } catch (AppException ex) {
                boolean transientFailure = ex.code() == ErrorCode.GEMINI_UNAVAILABLE
                        || ex.code() == ErrorCode.PARSE_ERROR;
                if (!transientFailure) {
                    throw ex;
                }
                last = ex;
                log.warn("Gemini lần {} thất bại ({}), {}", attempt, ex.code(),
                        attempt < MAX_ATTEMPTS ? "thử lại" : "bỏ cuộc");
                if (attempt < MAX_ATTEMPTS) {
                    sleepBackoff();
                }
            }
        }
        throw last;
    }

package com.hiepnn.ieltstranslator.quiz;

import org.springframework.stereotype.Component;

import java.util.HashSet;
import java.util.List;
import java.util.Locale;
import java.util.Set;

/**
 * Kiểm tra từng item Gemini trả về. Hàm thuần — không DB, không mạng.
 *
 * <p>Khác {@code DistractorValidator} một cách CÓ CHỦ Ý: ở đây loại TỪNG item hỏng rồi
 * lấy tiếp phần còn lại, không giết cả lô. Một lô 10 câu mà hỏng 1 câu thì 9 câu kia vẫn
 * dùng được, và người dùng đang đứng chờ — bắt họ đợi thêm một lượt gọi Gemini nữa chỉ
 * vì một câu hỏng là đắt vô lý. Bên mồi nhử thì ngược lại: việc chạy nền, không ai chờ.
 */
@Component
public class QuizItemValidator {

    /** Chỗ trống trong câu điền từ. Đúng ba gạch dưới, khớp với prompt. */
    public static final String BLANK = "___";

    private static final int REQUIRED_OPTIONS = 4;

    /**
     * Hợp lệ khi: câu chứa {@code ___}, đáp án không rỗng, và đáp án KHÔNG xuất hiện
     * nguyên văn ở phần còn lại của câu (bỏ phân biệt hoa thường). Đáp án lộ trong đề là
     * lỗi Gemini hay mắc nhất và cũng là lỗi làm câu hỏi mất sạch giá trị.
     */
    public boolean isValidFillBlank(String sentence, String answer) {
        if (sentence == null || answer == null || answer.isBlank()) {
            return false;
        }
        if (!sentence.contains(BLANK)) {
            return false;
        }
        String withoutBlank = sentence.replace(BLANK, " ").toLowerCase(Locale.ROOT);
        return !withoutBlank.contains(answer.trim().toLowerCase(Locale.ROOT));
    }

    /** Hợp lệ khi: đúng 4 lựa chọn, không rỗng, không trùng nhau, index trong 0..3. */
    public boolean isValidCollocation(List<String> options, Integer correctIndex) {
        if (options == null || correctIndex == null || options.size() != REQUIRED_OPTIONS) {
            return false;
        }
        if (correctIndex < 0 || correctIndex >= REQUIRED_OPTIONS) {
            return false;
        }
        Set<String> seen = new HashSet<>();
        for (String option : options) {
            if (option == null || option.isBlank()) {
                return false;
            }
            if (!seen.add(option.trim().toLowerCase(Locale.ROOT))) {
                return false;
            }
        }
        return true;
    }
}

package com.hiepnn.ieltstranslator.quiz;

import org.springframework.stereotype.Component;

import java.util.Locale;

/**
 * Chấm hai loại quiz chấm được tại chỗ. Hàm thuần — không DB, không mạng, không Gemini.
 */
@Component
public class QuizGrader {

    /**
     * So với đúng dạng từ đã bị che. CỐ Ý không lemmatize: đề che dạng "mitigated" thì
     * người học phải viết "mitigated". Chấp nhận "mitigate" là dạy sai — chia động từ
     * đúng chính là thứ đang luyện.
     */
    public boolean gradeFillBlank(String userAnswer, String expected) {
        if (userAnswer == null || expected == null) {
            return false;
        }
        String given = userAnswer.trim();
        return !given.isEmpty()
                && given.equalsIgnoreCase(expected.trim());
    }

    /**
     * Answer đi trên đường truyền LUÔN là string (một hình dạng, không union). Chuỗi
     * không parse được thành index tính là SAI, không phải lỗi — người dùng gõ bậy
     * không phải sự cố hệ thống.
     */
    public boolean gradeCollocation(String userAnswer, int correctIndex) {
        if (userAnswer == null) {
            return false;
        }
        try {
            return Integer.parseInt(userAnswer.trim()) == correctIndex;
        } catch (NumberFormatException ex) {
            return false;
        }
    }
}

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;

import java.util.List;

/**
 * Chọn từ đưa vào đề. Đây là chỗ DUY NHẤT module quiz chạm tới bảng srs_card, và nó
 * chỉ ĐỌC.
 *
 * <p>Vì sao native query chứ không inject SrsCardRepository: giữ chiều phụ thuộc sạch.
 * quiz không import gì từ package srs, nên không có đường nào để lỡ tay gọi một method
 * ghi. Bất biến "quiz không tác động tới lịch SRS" được QuizSrsIsolationIT kiểm chứng.
 *
 * <p>Extends JpaRepository trên QuizItem chỉ để có một repository interface hợp lệ cho
 * Spring Data; nó không dùng method kế thừa nào.
 */
@Repository
public interface QuizCandidateRepository extends JpaRepository<QuizItem, Long> {

    /**
     * Từ đã ôn ít nhất một lượt, ưu tiên từ ít bị hỏi nhất, rồi tới từ hay quên nhất.
     * Từ chưa ôn lần nào (repetitions = 0) KHÔNG được đưa vào quiz — chưa gặp mặt thì
     * hỏi là phạt oan.
     */
    @Query(value = """
            SELECT v.id
            FROM vocab_entry v
            JOIN srs_card c ON c.vocab_entry_id = v.id
            LEFT JOIN quiz_item qi ON qi.vocab_entry_id = v.id
            LEFT JOIN quiz_attempt qa ON qa.quiz_item_id = qi.id
            WHERE c.repetitions >= 1
            GROUP BY v.id, c.lapses
            ORDER BY count(qa.id) ASC, c.lapses DESC, v.id ASC
            LIMIT :limit
            """, nativeQuery = true)
    List<Long> findCandidates(@Param("limit") int limit);
}

public record GenerateQuizRequest(

        @Positive(message = "phải lớn hơn 0") Integer count,
        List<QuizType> types

        boolean hasIds = vocabIds != null && !vocabIds.isEmpty();
        boolean hasCount = count != null;
        return hasIds ^ hasCount;
    }

    /** types rỗng hoặc thiếu → mặc định cả ba loại (spec mục 3.9). */
    public List<QuizType> effectiveTypes() {
        return (types == null || types.isEmpty()) ? List.of(QuizType.values()) : types;
    }

**Nhóm:** extension. **Phụ thuộc:** không.

Spec mục 3.12. `ApiClient.request()` hiện gọi `fetch` trần — backend treo là spinner quay mãi.

**Rủi ro hồi quy:** `request()` là đường đi của **mọi** endpoint Phase 1 và Phase 2 (`translate`, `saveVocab`, `searchVocab`, `deleteVocab`, `getDueCards`, `submitReview`, `srsStats`, `health`). Sửa sai ở đây là hỏng toàn bộ extension. Cụ thể:

- **`init.signal` do caller truyền vào sẽ bị `AbortSignal.timeout()` ghi đè** nếu spread sai thứ tự. Hiện chưa caller nào truyền `signal`, nhưng đặt `signal` **sau** `...init` là điều kiện để hành vi ổn định.

```ts
  private async request<T>(path: string, init: RequestInit,
                           timeoutMs: number = DEFAULT_TIMEOUT_MS): Promise<T> {
    const baseUrl = await this.baseUrlProvider();

    let response: Response;
    try {
      response = await fetch(`${baseUrl}${path}`, {
        ...init,
        headers: { 'Content-Type': 'application/json', ...(init.headers ?? {}) },
        // signal đặt SAU ...init có chủ ý: timeout của tầng này là bất biến, không cho
        // caller vô tình bỏ qua bằng cách truyền signal riêng.
        signal: AbortSignal.timeout(timeoutMs),
      });
    } catch (error) {
      // AbortSignal.timeout() ném DOMException tên 'TimeoutError'; mất mạng ném TypeError.
      // Hai chuyện khác nhau: một cái là backend chậm, một cái là backend không có ở đó.
      // Gộp thông điệp là bắt người dùng đi kiểm tra sai chỗ.
      const timedOut = error instanceof DOMException && error.name === 'TimeoutError';
      throw timedOut
        ? apiError('BACKEND_DOWN',
            `Backend không trả lời trong ${Math.round(timeoutMs / 1000)} giây. Thử lại, hoặc xem log docker compose.`,
            true)
        : apiError('BACKEND_DOWN',
            'Không kết nối được backend. Kiểm tra docker compose đã chạy chưa.', true);
    }
    /* ... phần còn lại GIỮ NGUYÊN ... */
  }
```

## Việc cần người thật làm

Không agent nào tự làm được, phải có người ngồi trước Chrome:

1. **Khởi động lại backend** sau Task A2 để Flyway chạy `V5` (`docker compose up -d --build`, hoặc restart run config "Backend local").
2. **Build lại và tải lại extension unpacked** từ `extension/dist/` sau Task B3.
3. **Ôn ít nhất một thẻ** ở tab Ôn tập trước khi kiểm thử Quiz — sổ chưa có từ nào `repetitions >= 1` thì Quiz đúng ra phải trả rỗng, và người kiểm thử sẽ tưởng là lỗi.
4. **Toàn bộ Step 8 của Task C1** — 8 mục kiểm chứng thủ công.
5. **Đánh giá chất lượng đề** bằng mắt: 5–10 câu mỗi loại. Đây là thứ test không bắt được. Câu `FILL_BLANK` chung chung, hay ba mồi nhử collocation sai một cách lố bịch, đều là "prompt cần tune" chứ không phải "code hỏng". Sửa file prompt → **tăng `version:`** → đề cũ tự hết hiệu lực.
6. **Quyết định 4 câu hỏi mở bên dưới** — Q1 và Q2 chặn Task A5/A6 nếu người dùng không đồng ý với mặc định đã chốt trong plan.

### Câu hỏi mở — cần quyết trước khi làm A5/A6

**Q1 — `count` là số câu hay số từ? (chặn A5, A6)**
Spec mục 3.3 dùng `LIMIT :count` trên **từ**; mục 3.13 lại là ô "chọn số câu". Hai cách hiểu ra kết quả khác nhau gấp ba: `count=10` + 3 loại là 10 câu hay 30 câu.
**Plan đang chốt: `count` = số câu hỏi, mỗi từ một câu, loại xoay vòng theo `types` đã tick.** Lý do: người dùng gõ "10" rồi nhận 30 câu và 2 lượt gọi Gemini không xin là hành vi tệ.
→ Cần `techlead` hoặc người dùng xác nhận. Đổi ý sau khi A5 xong thì phải sửa cả `QuizGenerator.buildItems` lẫn `QuizService.generate`.

**Q2 — Timeout sinh đề 35s phía extension có đủ không? (chặn B2 nếu đổi)**
Spec mục 3.11 đặt timeout backend **30s cho mỗi call Gemini**, không phải cho cả request. Với `types` đủ ba loại, backend gọi **hai** lượt Gemini tuần tự, mà `GeminiClient` còn retry một lần khi 5xx/parse lỗi. Xấu nhất: `2 loại × 2 lần × 30s + backoff ≈ 122s`. Extension bỏ cuộc ở 35s và hiện "backend không trả lời", trong khi backend vẫn đang chạy và vẫn lưu item vào DB — người dùng bấm Tạo đề lần nữa sẽ thấy đề xuất hiện "một cách bí ẩn".
Ba hướng, cần `techlead` chọn:
- (a) Nâng timeout `generateQuiz` lên ~80s và hiện tiến trình rõ hơn ở panel — đơn giản nhất, nhưng 80s chờ là dài.
- (b) Panel gọi **một loại mỗi lần** (`types` một phần tử), ghép kết quả ở client — mỗi request về đúng trong 35s, feedback sớm hơn; đổi lại `QuizTab` phức tạp hơn.
- (c) Giữ 35s và chấp nhận: lần đầu có thể quá hạn, lần bấm lại sẽ nhanh vì item đã lưu — rẻ nhất, nhưng lần dùng đầu tiên của người dùng là lần tệ nhất.
**Đề xuất của PM: (b).** Nó xử lý gốc vấn đề chứ không nới số, và hợp với thực tế "mỗi loại một call" mà spec đã chốt.

**Q3 — Cột `improved_version` trong `quiz_attempt`: có lưu không? (chặn A2)**
Spec mục 3.8 không có chỗ chứa, mục 3.9 lại trả về trong response. Plan đang **thêm cột**. Phương án thay thế: không lưu, chỉ trả về — lịch sử làm bài mất phần giá trị nhất của `FREE_WRITE`. Bảng còn mới nên thêm bây giờ là miễn phí; thêm sau là một migration nữa. → `techlead` xác nhận.

**Q4 — Giới hạn độ dài câu trả lời `FREE_WRITE`? (không chặn, nhưng nên chốt trước A6)**
Spec không nói. `ErrorCode.TEXT_TOO_LONG` đã có sẵn và `TranslationService.MAX_TEXT_LENGTH = 1500` là tiền lệ. Không giới hạn thì một lần dán nhầm 50KB đi thẳng vào prompt chấm và đốt token thật.
**Đề xuất: chặn ở 1000 ký tự, ở cả hai phía** (backend `AppException.of(ErrorCode.TEXT_TOO_LONG, …)` và `maxLength` trên `<textarea>`), giống hệt cách giới hạn 1500 đang được chặn hai phía. Không thêm `ErrorCode` mới.

**Q5 — Loại nào ra trước trong một đề trộn? (không chặn)**
Spec không nói. Plan để thứ tự theo `vocabIds` (tức theo độ ưu tiên ứng viên), nên các loại nằm xen kẽ do xoay vòng. Nếu muốn "làm hết `FILL_BLANK` rồi mới tới loại khác" thì nói trước khi A6 xong — đổi sau là sửa `QuizService.generate` và `QuizTab`.
